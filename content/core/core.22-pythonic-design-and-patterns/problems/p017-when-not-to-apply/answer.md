**A. Factory of factories.** It claims to hide *which* greeter is built, so callers do not depend on concrete classes. In Python a class is already a callable and a function can return anything, so `Greeter("en")` or a plain function `greet(name, language="en")` is enough. Simple version: `GREETINGS = {"en": "Hello, ", "es": "Hola, "}` and `def greet(name, language="en"): return GREETINGS[language] + name`. The heavier design pays off when whole *families* of objects must be swapped together (a UI toolkit with matching buttons, menus and dialogs per platform) and the choice is made in one place.

**B. Four ABCs for one class.** It claims to define clear contracts so that parts can be replaced. But one class implements all four, and nobody else does, so the contracts protect nothing and every change touches five places. Python uses duck typing: whoever needs `save` just calls `.save`. Simple version: one class with four methods, or functions. If a caller wants a type hint, one small `Protocol` for the *one* method it uses is enough. ABCs are worth it when a library has many third-party implementations and you want a clear error at class-creation time if a method is missing.

**C. Singleton.** It claims to guarantee exactly one configuration object that everyone shares. In Python a module is already created once and cached in `sys.modules`, so `config.py` with `values = {}` and `import config` gives the same object everywhere, without `__new__` tricks. Simple version: a module-level object, or better, create one `Config` in `main` and pass it to the code that needs it (this also keeps tests independent). A real single instance is worth enforcing when two copies would corrupt an exclusive resource, such as one connection to a device or a lock file.

**D. Strategy for `len`.** It claims to let you swap the algorithm without changing the caller. But the "strategy" has no state and one line, and functions are first-class objects: `def run(items, measure=len): return measure(items)`, and `run(words, measure=lambda w: sum(map(len, w)))` swaps it. A strategy *class* becomes worth it when the algorithm has its own configuration and state (for example a retry policy with limits, a counter and logging) that must travel together.

**Rule of thumb:** add the pattern when you can name the pain it removes today; do not add it because it might help later.
