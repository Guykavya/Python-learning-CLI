## Model answer

**Plan (2 hours, 6 problems)**

1. **Minutes 0 to 8:** read **all** problems, not only A. Mark each as "clear idea", "maybe", "no idea". Check the constraints of each (what complexity is needed).
2. **Order:** solve the problems in the order of the board (how many solved), not in the printed order. Start with the easiest clear one.
3. **Time boxes:** about 15 minutes for A, 25 for B, 35 for C. If a problem takes more than twice its box and I have no new idea, **skip** it and come back later.
4. **Before submitting:** test the samples, one smallest case (`n = 1`), and one case with equal numbers or the largest values. A wrong submission costs 10 minutes of penalty and nerves.
5. **When stuck:** write a brute force for the small version, find a pattern; if still stuck after the box, switch to another problem.
6. **Last 10 minutes:** no new problem. Re-read the problem I solved to check the output format and the constraints; resubmit a fix only if I can test it.
7. **During the contest:** keep notes on a paper: problem, idea, time at which I started and stopped.

**Upsolving (next day)**

1. For each problem I did not solve: try again for 30 to 45 minutes **without** the editorial.
2. Then read the editorial, and **re-implement the solution without looking** at it.
3. For a problem I solved slowly: find out where the time went (idea, code, bug) and write it in the log.
4. Write one sentence per problem in an **upsolve log**: the idea, the trick, the time.
5. Also try one more problem of the same rating or topic (a "next rung").

**Checklist: your answer should mention**
- [ ] read **all problems first**, and use the board (how many solved)
- [ ] **time boxes** with a **skip rule**
- [ ] test the sample plus a **smallest and an extreme case** before submitting
- [ ] what to do when **stuck** (brute force, switch)
- [ ] the **last minutes**: no new problem, check format
- [ ] **upsolve**: retry alone, then editorial, then re-implement
- [ ] a **log** of ideas and times
